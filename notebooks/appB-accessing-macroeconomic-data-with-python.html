B. Accessing Macroeconomic Data with Python

Learning goals

Macroeconomics runs on data: GDP, unemployment, inflation, interest rates, exchange rates. All of these are free to download, and Python can download them for you. Every example here downloads live data, so your numbers may be more recent than the ones printed on the website. By the end of this appendix you will be able to:

  • name the main sources of macroeconomic data and say what each one is good for;
  • tell apart the four ways of getting data into Python: a specialized library, a general library for many agencies, a collection of many sources in one place, and reading a file straight from its web address;
  • download series from FRED, the World Bank, the IMF, the ECB, Eurostat and the OECD with a few lines of code;
  • read the Penn World Table, the Maddison Project Database and Our World in Data directly from their files on the internet;
  • compare the same number from several sources and explain why they differ;
  • keep good habits: find the right series code, check units and dates, save a copy and record your sources.

B.1 A map of macroeconomic data sources

The table lists the sources used most often in macroeconomics, and in this book. Each row says who publishes the data, what they cover and the easiest way to reach them from Python. You do not need to remember it: come back to it when you look for a series.

Most numbers start life at a national statistical office, such as the U.S. Bureau of Economic Analysis (BEA) or Bureau of Labor Statistics (BLS). FRED, the World Bank, the IMF and the others collect these numbers, check them and put them in one place. That is why the same series often appears in several sources.

B.1.1 Four ways to get data into Python

Way Example in this appendix Good Watch out
1. A specialized library for one source wbgapi (World Bank), imfp (IMF), fredapi (FRED), eurostat easy, with search functions and tidy tables one library per source; libraries change over time
2. A general library that speaks SDMX, a data standard shared by many agencies sdmx1 for the ECB, IMF, OECD and Eurostat the same code for many agencies you must learn each dataset’s “key” (its dimensions)
3. A collection of many sources in one place dbnomics one library and one search website for many providers its copy can lag a few months behind the original
4. Read a file straight from its web address FRED CSV, Penn World Table, Maddison, Our World in Data works for any file on the internet, with pandas alone you must find the address, and it can change

B.1.2 Three ideas to keep in mind

  • Series codes. Every series has a short code. UNRATE is the U.S. unemployment rate in FRED, and NY.GDP.PCAP.KD is GDP per person in constant dollars at the World Bank. Codes are precise; names are not. The first step is always to find the right code, using the source’s website or a search function.
  • Units. Read the units before you compute anything: percent or fraction, dollars or thousands of dollars, current or constant prices, monthly or annual, seasonally adjusted or not.
  • Vintages. Statistical offices revise their numbers as better information arrives. The GDP growth rate you download today for 2024 may differ from the one published in 2025. Each release is a vintage. Always write down when you downloaded your data.

B.3 FRED

FRED (Federal Reserve Economic Data) is the first place to look for U.S. macroeconomic data, and it has many international series too. Every series has a page on the FRED website. For example, the U.S. unemployment rate lives at fred.stlouisfed.org/series/UNRATE: the code UNRATE is the last part of the address. To find a code, type what you want in the search box of the FRED website.

FRED gives you three routes into Python. We try all three.

B.3.1 Way 4: read the CSV file of a series

Every FRED series can be downloaded as a CSV file (a plain text table with values separated by commas) from an address that ends with its code. pd.read_csv reads a CSV file, and it accepts a web address as easily as a file on your computer. This route needs no extra library and no registration.

Python note. parse_dates=["observation_date"] tells pandas that this column holds dates, so that charts put them on a time axis. .tail() shows the last five rows of a table, .head() the first five.

# The address of a FRED series: a fixed beginning plus the series code
url = "https://fred.stlouisfed.org/graph/fredgraph.csv?id=UNRATE"
unrate = pd.read_csv(url, parse_dates=["observation_date"])
unrate.tail()

We will download several series, so we wrap these lines in a small function. Give it a code, and it returns the table, with the date column renamed to the shorter date.

def read_fred(code):
    """Download one FRED series as a table with the columns date and <code>."""
    url = "https://fred.stlouisfed.org/graph/fredgraph.csv?id=" + code
    table = pd.read_csv(url, parse_dates=["observation_date"])
    return table.rename(columns={"observation_date": "date"})

The consumer price index (CPI) is a price level. Inflation is its growth rate. With monthly data, the inflation rate over the past 12 months is

\[\text{inflation}_t = \left(\frac{\text{CPI}_t}{\text{CPI}_{t-12}} - 1\right) \times 100 .\]

In pandas, .shift(12) moves a column down by 12 rows, so each row can see the value from 12 months earlier.

cpi["inflation"] = (cpi["CPIAUCSL"] / cpi["CPIAUCSL"].shift(12) - 1) * 100

# Put unemployment and inflation side by side in one table, matched by date
fred = read_fred("UNRATE").merge(cpi[["date", "inflation"]], on="date")
fred = fred.rename(columns={"UNRATE": "Unemployment rate", "inflation": "Inflation rate (CPI, 12 months)"})
fred = fred[fred["date"] >= "1960-01-01"]
fred.tail()

B.3.2 Way 1: pandas-datareader

The library pandas-datareader reads FRED (and a few other sources) into a pandas table. Its advantage: you can ask for several series in one call, and it lines them up by date for you.

B.3.3 Way 1: fredapi, with a free API key

The library fredapi uses FRED’s official API (application programming interface: a web address designed for programs rather than people). It can also search FRED from Python. To use it you need a free API key, a personal password for programs:

  1. Create a free account at fred.stlouisfed.org and request a key on the API keys page. It is a string of 32 letters and digits.
  2. In Colab, click the key icon (Secrets) in the left sidebar, choose Add new secret, name it FRED_API_KEY, paste your key as its value, and switch on Notebook access.
  3. Run the cell below.

Never type a key directly into a notebook that you share: anybody who sees the notebook could use it. Colab Secrets keep it out of the notebook. Without a key, the cell below just prints a message and moves on.

Python note. try: runs a block of code, and except: says what to do if it fails, instead of stopping with an error. Here it fails outside Colab, or when no secret called FRED_API_KEY exists.

B.5 IMF: imfp

The International Monetary Fund publishes the World Economic Outlook (WEO) twice a year, in April and October. Its database has GDP growth, inflation, unemployment and government debt for about 190 countries, and, unlike most sources, forecasts for the next five years. The library imfp reads it, and every other dataset on the IMF’s data portal, in four steps:

  1. imf_get_dataflows(): which datasets exist?
  2. imf_get_datastructure(dataset): which dimensions does a dataset have (country, indicator, frequency)?
  3. imf_get_codelists(dimension, dataset): which codes can each dimension take?
  4. imf_get(dataset, {dimension: codes}): download the data.
import imfp

# Step 1: the IMF's datasets; .str.contains keeps the rows whose name contains a word
datasets = imfp.imf_get_dataflows()
print(len(datasets), "datasets")
datasets[datasets["name"].str.contains("World Economic Outlook")][["id", "name"]]

NGDP_RPCH is the growth rate of real GDP (“constant prices, percent change”). Step 4 downloads it for five countries. The columns TIME_PERIOD and OBS_VALUE hold the year and the value.

# Step 4: the data
weo = imfp.imf_get("WEO", {"COUNTRY": ["USA", "CHN", "IND", "DEU", "BRA"], "INDICATOR": "NGDP_RPCH"})
weo["year"] = weo["TIME_PERIOD"].astype(int)            # the years arrive as text: make them numbers
names = {"USA": "United States", "CHN": "China", "IND": "India", "DEU": "Germany", "BRA": "Brazil"}

B.9 Reading data files straight from the web

Some of the most important datasets in macroeconomics have no Python library. They are published as files, in CSV, Excel or Stata format. pandas reads all of them from a web address:

B.9.1 The Penn World Table

The Penn World Table (PWT) measures real GDP, employment, hours, capital and productivity in a way that can be compared across countries. Chapters 3 to 6 use it a lot. Its files are stored at DataverseNL, a data archive. Each dataset there has a permanent identifier (a DOI), and Dataverse has an API that lists the files of a dataset with their numbers.

B.10 Putting it together: one number, many sources

How fast has income per person grown in the United States since 2000? Five of our sources can answer, and we already know how to reach each of them. We collect U.S. real GDP per person from each one into a single table with one column per source.

  • FRED: series A939RX0Q048SBEA (real GDP per capita, quarterly), averaged over each year.
  • World Bank: NY.GDP.PCAP.KD (constant 2015 dollars).
  • IMF WEO: NGDPRPC (GDP per capita, constant prices, national currency).
  • Penn World Table: rgdpna / pop (real GDP from the national accounts, per person).

The five columns are in different units: chained 2017 dollars, constant 2015 dollars, PPP dollars and so on. To compare them, we turn each into an index equal to 100 in 2000. Then we compute the average annual growth rate between 2000 and the last year that all five sources cover:

\[g = \left(\frac{y_{\text{end}}}{y_{2000}}\right)^{1/(\text{end} - 2000)} - 1 .\]

END = int(sources.dropna().index.max())       # the last year with all five sources
index = 100 * sources.loc[2000:END] / sources.loc[2000]
growth = 100 * ((sources.loc[END] / sources.loc[2000]) ** (1 / (END - 2000)) - 1)
print(f"Average annual growth of U.S. real GDP per person, 2000-{END}, percent:")
print(growth.round(2).to_string())

What to notice. The five sources tell the same story, but not with exactly the same numbers. In our run, FRED, the World Bank and the IMF, which all copy the latest official U.S. numbers, agree almost exactly. The Penn World Table and the Maddison Project show slower growth. Why do sources differ?

  • Vintages. Each source copied the official U.S. numbers at a different time, and the BEA revises GDP every year. FRED is updated within days; the Penn World Table and the Maddison Project only every few years.
  • Population. GDP per person divides by population, and the sources use different population estimates (from the Census Bureau, the United Nations or their own).
  • Prices and methods. The sources measure real GDP in different base years and, for the Penn World Table and the Maddison Project, convert it with their own international prices.

The lesson: always say where a number comes from, and compare sources when a result matters.

B.11 Good habits and going further

B.11.1 Keep a copy and record your sources

  • Save what you download. Sources change, revise and sometimes move their files. table.to_csv("name.csv") saves a table in the Colab session (see the Files icon in the left sidebar). A Colab session is temporary, so download the file to your computer from there, or save it in your Google Drive.
  • Write down the source, the series code and the date next to every result, as the Sources notes in this book do. TODAY, defined in the setup cell, holds the date of your download.
  • Check the units and the latest date before you compute anything (.tail() is your friend).
  • Keep keys secret. Store API keys in Colab Secrets, never in the notebook.
  • Be polite to the servers. Download what you need once and reuse the table, instead of downloading the same data again in every cell.
# Save a table with the download date in its name
file_name = f"us_unemployment_inflation_{TODAY}.csv"
fred.to_csv(file_name, index=False)
print("Saved", file_name)

B.11.2 When a download fails

Servers are sometimes down, busy or changed. A download that fails stops the notebook with an error, often an HTTPError or a ConnectionError. Wait a minute and run the cell again. If it keeps failing, try and except let you fall back on a copy, such as the prepared file of this book:

try:
    unemployment_rate = read_fred("UNRATE")
    print("Downloaded from FRED")
except Exception as problem:
    print("FRED did not answer:", problem)
    unemployment_rate = pd.read_csv(BOOK_DATA + "ch07/fig7-2.csv", parse_dates=["date"])
    print("Using the copy stored in the book's repository instead")

B.12 Concluding remarks

  • Macroeconomic data are free. The main sources are FRED, the World Bank, the IMF, the OECD, Eurostat, the ECB and the BIS for official statistics, and the Penn World Table, the Maddison Project and Our World in Data for comparisons across countries and over the long run.
  • Python reaches them in four ways: specialized libraries (wbgapi, imfp, fredapi, eurostat), a general SDMX library (sdmx1), a collection of many sources (dbnomics), and reading CSV, Excel or Stata files straight from their web addresses with pandas.
  • Every series has a code. Find it first, then check the units and the latest date of what you downloaded.
  • The same number differs a little across sources because of vintages, population estimates and methods. Always record where and when you got your data.
  • Every chapter of this book reads prepared copies of these data from its GitHub repository. You can now go back to the original sources, update them, and extend any chapter to other countries and years.
